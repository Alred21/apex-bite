## What to build

Use the new controls, recovery, driver, and Racing Line together throughout Time Trial and Corner Drills, with coherent records and measured browser performance.

## Acceptance criteria

- [ ] Complete a normal 12-lap Time Trial with the integrated changes; retain measured Sector splits, contact/Clean Lap status, stable results, restart, unlimited practice, and legacy-record preservation.
- [ ] Exercise a stop/back-up/resume recovery near a Barrier and Start/Finish or Sector boundary, plus keyboard remapping and gamepad recovery, without input latches or manufactured timing.
- [ ] Exercise all eleven Turn drills and five Corner Complex drills against the selected Reference Lap and actual Apex targets; verify Ghost/timing/coaching consistency.
- [ ] Review both camera views with driver, line, and Ghost Karts visible; correct integration defects in hand grip, wheel framing, clipping, color readability, or reverse feedback.
- [ ] Measure production startup/search cost and warmed frame timing in both camera views at a recorded viewport, DPR, quality preset, hardware, and browser; target 60 FPS and report distributions/hitches as well as average FPS.
- [ ] Use the existing documented local hardware for comparative evidence and distinguish it from unmeasured laptop claims. Check a full session for accumulating costs.
- [ ] Run the relevant public-session suites and real-browser checks, then required type checking and production build. Do not defer slice-specific verification to this final ticket.
- [ ] Publish an iteration-3 implementation report with annotated line comparison, driver views, measured improvements, asset sources/licenses, validation outcomes, and remaining limitations.
- [ ] Deliver repository changes and review evidence; production deployment is outside this ticket unless separately authorized.
